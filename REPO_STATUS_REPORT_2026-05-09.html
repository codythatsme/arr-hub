Executive Verdict

What exists

ARR Hub is a substantial local-first media automation application. It has a TanStack Start/TanStack Router frontend, tRPC API, Effect service layer, Drizzle/SQLite data model, built-in adapters for qBittorrent/SABnzbd/Torznab/Newznab/Plex/Jellyfin, an acquisition and release-policy pipeline, scheduler, Plex activity analytics, notifications, plugin loading, onboarding, import from Radarr/Sonarr, Docker assets, and a sizeable unit/integration test suite.

What is actually working right now

The TypeScript app compiles, formats, tests, and builds successfully. The backend service architecture is broadly wired. However, the current local SQLite database in data/arr-hub.db is not in a clean runnable product state: it has users and API keys, no onboarding setup state, no Drizzle migration tracking table, and is missing current schema tables for plugins and notifications.

Most important operational finding: With the default DATABASE_PATH=data/arr-hub.db, the local app will likely redirect to onboarding because setup_state is empty, but onboarding cannot create the admin because users already exist. The same local database also lacks plugins, notification_channels, and notification_deliveries, so those runtime features can fail until the database is reset, pushed, migrated with a proper baseline, or manually repaired.

Architecture And Stack

Application Framework

  • Bun + TypeScript ESM package.
  • TanStack Start, TanStack Router, TanStack Query.
  • React 19, Tailwind CSS 4, Radix UI, lucide-react, Recharts.
  • Vite 7 with React compiler plugin, TanStack devtools, Nitro node-server output.

Backend Architecture

  • tRPC 11 routers as the main application API.
  • Effect services wired via AppLive and ManagedRuntime.
  • Direct HTTP JSON wrappers for queue/system endpoints.
  • Background scheduler loop and notification worker started by runtime bootstrap.

Persistence

  • SQLite through better-sqlite3, @effect/sql-sqlite-node, and Drizzle.
  • Default database path: data/arr-hub.db.
  • Drizzle schema in src/db/schema.ts.
  • 7 migration files under drizzle/.

The repo also contains a large vendor/ reference tree for Effect, Prowlarr, Radarr, Sonarr, Tautulli, and Seerr; this report treats those as reference/vendor material, not ARR Hub implementation code.

Database And Local Data State

Local database drift

src/db/schema.ts defines tables for plugins and notifications, and migrations 0005 and 0006 create them. The current data/arr-hub.db does not have those tables. It also has no __drizzle_migrations table, so migration history is not tracked in this local database.

Local onboarding conflict

The local DB has 44 users and 66 API keys, but setup_state has 0 rows. The app's auth guard treats missing setup state as incomplete setup and redirects to onboarding; onboarding admin creation rejects when a user already exists. This is likely a local runtime blocker.

Prioritized Gaps And Risks

1. Repair local database state before trusting manual app testing

The checked/default local SQLite DB is both behind schema and logically stuck in setup. A clean reset, Drizzle push, migration baseline, or manual setup-state repair is needed before judging UI flows in the browser against data/arr-hub.db.

2. Finish post-onboarding integration settings UI

Indexers, Download Clients, and Media Servers have real services and routers, but the settings pages are placeholders. This is the largest visible product gap.

3. Expose media acquisition workflows in UI

Movies/TV backend supports add/search/evaluate/grab/search-and-grab, but list/detail pages currently do not surface those workflows. README claims more UI than exists.

4. Fix Docker-backed qBittorrent smoke

The docker smoke script passed SABnzbd and then failed qBittorrent auth. This could be a harness issue with the current linuxserver/qbittorrent image or an adapter/login compatibility issue. It blocks claiming end-to-end qBittorrent Docker interop today.

5. Add browser-level coverage

There are many service tests, but no E2E coverage for onboarding, auth redirects, placeholder-vs-real pages, dashboard polling, or settings workflows.

6. Add CI

The repo has strong local scripts but no first-party workflow files to enforce typecheck/lint/test/build on PRs.

7. Reduce build warnings and chunk weight

Build passes, but the main and stats chunks are large. The lint warnings are not correctness failures, but they are noisy enough to obscure real regressions over time.
